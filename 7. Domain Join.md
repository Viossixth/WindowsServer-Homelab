**Phase 7: Domain Join**

In this Phase i encountered a lot of issues and had to troubleshoot a lot. The plan was to RDP into VM2, set DNS to point towards the Domains static IP Address and join the domain.

Logging into VM2 as a created user was an issue. I always had a username error and ended up figuring it out that i should state the domain name alongside user name. Instead of IMaluleke i should use LAB/IMaluleke. Secondly the created uses were not permitted to use RDP. I then had to log into VM2 as a root user (azureuser) and configure the new settings for the created users. I changed the restricted group settings to allows the selected users to use RDP.

I then joined VM2 into the domain via the root user of VM2 in the interest of time. I configured DNS to point towards the static IP and joined the domain.

After joining VM2 into the Domain. I logged out of the root user. I then logged into VM2 using RDP as a user created in Phase 3. That's when i encountered another issue. The Group Policy worked as seen by a black wallpaper instead of the default windows wallpaper. Now i had to troubleshoot why the wallpaper wasn't displaying properly. I found that the root path used was correct in VM1 but doesn't exist in VM2 so when the Group Policy is applied to another user , the Group Policy can't find it. To solve this I created a new folder which isn't dependent on the user but exists on the shared folder for the DC. This solved the issue and the wallpaper now rendered properly. I ran a PowerShell script see all the Group Policy's active at the moment.
